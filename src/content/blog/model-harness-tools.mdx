"The AI did it" is not a sentence an engineer gets to say. Not because it's imprecise — because it's wrong. "The AI" is three different things doing three different jobs, and until you know which one moved, you don't have a diagnosis. You have a shrug.

## It's Not One Machine, It's Three

The model predicts text. That's the entire job description. Claude, GPT, Gemini — pick your family — each one takes tokens in and produces tokens out. A model has never opened a file, run a command, or touched anything outside its own weights. Feed it a question about your codebase and it will answer confidently whether or not it has ever seen your codebase, because seeing things was never in the job description.

The harness is the software wrapped around the model that runs the loop: assemble context, send it to the model, read what comes back, execute any tool calls in it, repeat. Claude Code is a harness. Claude.ai is a harness. Cursor and GitHub Copilot are harnesses. The same model can sit inside any of them and behave completely differently, because the harness decides what the model gets to see and what it's allowed to do about it.

The tools are the only part that touches anything real. Read a file. Run a command. Hit an API. Everything else is prediction and plumbing.

This is why the same model produces different behavior in different products — identical weights, completely different wiring around them. It's why an agent "deciding" to run your tests is really the model emitting a structured string that the harness parses and executes; the model has never executed anything in its life. And it's the first question of every diagnosis: wrong output, look at the context the harness assembled. Nothing happened, check whether a tool call actually fired, or was merely described — confidently, in prose.

## The Terminal Is a Master Key

Here's where the distinction stops being academic. Give a coding agent a terminal and a filesystem, and you haven't handed it one new tool. You've handed it every tool already installed on the machine.

`gh` hands it the whole forge — PRs, issues, releases. `az` hands it everything in the subscription. `aws` hands it the same idea under a different flag. None of these were built for the agent. The moment it can open a shell, it inherits all three, instantly, with zero integration work from anyone.

That's the entire difference between a chatbot in a browser tab and a coding agent in a terminal. The chatbot's harness hands the model a fixed menu — search the web, render an artifact, maybe read a document. The coding agent's harness hands the model a shell prompt, and a shell prompt isn't a tool. It's a door to every tool the machine has ever had installed on it, present and future.

An authenticated CLI in the hands of an agent can do whatever that CLI can do: open PRs across every repo in the org, spin up or tear down cloud resources, ship whatever's sitting in the current directory. This is the whole reason permission prompts exist, and the whole reason clicking "approve all" is a decision and not a formality.

## Somebody Granted That Access

So when something goes wrong — a branch force-pushed, a resource group gone, prod written to — "the AI did it" describes nothing. The model emitted a tool call. The harness executed it. And a human, earlier, decided that harness got to hold those credentials in the first place.

Every postmortem I've read that stops at "the AI did it" stops one sentence before the useful part. The model doesn't get root-cause credit or root-cause blame — it can't, it never touched anything. Accountability lives in the harness and in whoever configured its access, because those are the only two things in the sentence actually capable of doing damage.

Next time it happens, don't ask what the AI did. Ask what the harness was allowed to run, and who allowed it. That's usually the whole incident report.
